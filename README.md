# Система управления приютом для животных (PostgreSQL)

Реляционная база данных для учета животных, медицинского обслуживания, складского хозяйства и процесса усыновления.

## Структура проекта

*   `shelter.sql` — Полный SQL-скрипт, содержащий:
    *   DDL (определение структуры таблиц, ограничений, индексов и триггеров).
    *   DML (заполнение тестовыми данными с реалистичными историями болезней).
    *   Аналитические запросы (демонстрация возможностей SQL).
*   `README.md` — Документация проекта.

## Архитектура и ключевые решения

Схема спроектирована с учетом требований 3НФ и специфики бизнес-процессов приюта. Особое внимание уделено сохранению историчности данных и автоматической синхронизации состояния системы.

### 1. Разделение ответственности и историчность
*   **Животные (`animals`):** Хранят базовую информацию и текущие статусы. Записи никогда не удаляются физически после смерти или усыновления, чтобы сохранить медицинскую статистику и юридическую историю.
*   **История событий:** Каждое изменение фиксируется отдельной записью:
    *   `medical_records`: Журнал вмешательств (осмотры, операции, лечение).
    *   `health_metrics`: Временной ряд измерений (вес, температура, BCS).
    *   `adoptions`: История передач животного владельцам (включая возвраты).
*   **Защита от противоречий:**
    *   Проверка `birth_date <= intake_date` (нельзя поступить раньше, чем родился).
    *   Проверка `return_date >= adoption_date` (нельзя вернуть животное раньше, чем забрали).
    *   Частичный уникальный индекс гарантирует отсутствие двух активных усыновлений для одного животного.

### 2. Складской учет с автоматической синхронизацией
Модель разделена на три слоя для гибкости и точности:
*   `products`: Статический каталог товаров.
*   `stock_moves`: Журнал движений (приходы/расходы). Является единственным источником истины об изменениях.
*   `inventory`: Текущий баланс остатков.

**Ключевая особенность:** Реализован триггер `trg_apply_stock_move`, который автоматически пересчитывает остатки в таблице `inventory` при каждой новой записи в `stock_moves`. Это исключает рассинхронизацию между историей операций и текущими запасами без участия приложения.

### 3. Целостность данных
*   **FOREIGN KEY:** Обеспечивают ссылочную целостность. Используется `ON DELETE CASCADE` для дочерних записей (медкарты), теряющих смысл без родителя, и `RESTRICT` для критичных связей (товары на складе).
*   **CHECK Constraints:** Жесткая валидация доменов значений (статусы жизненного цикла, типы медицинских процедур, шкала BCS 1-9, положительность сумм расходов).
*   **Транзакции:** Использование `BEGIN/COMMIT` для атомарного выполнения связанных операций (например, одновременное обновление статуса животного и создание медкарты о выздоровлении).

### 4. Аналитические возможности
Запросы демонстрируют работу с различными уровнями сложности SQL:
*   **JOIN:** Связывание разрозненных таблиц (медкарты + имена животных).
*   **GROUP BY + HAVING:** Агрегация затрат и фильтрация групп по итоговым суммам.
*   **CASE WHEN:** Динамическое вычисление статусов («Тревога по запасам», «Вердикт здоровья») без хранения избыточных флагов в БД.
*   **Window Functions (`ROW_NUMBER()`):** Выбор последнего актуального замера веса/BSC для каждого животного (паттерн Top-N per group).
*   **CTE (`WITH`):** Модульная структура сложных запросов для улучшения читаемости.

## Как запустить

### Требования
*   Установленный PostgreSQL (версия 14+).
*   Доступ к терминалу (Linux/macOS) или графическому клиенту (DBeaver, pgAdmin).

### Способ 1: Через командную строку (Рекомендуется)

1.  Создайте новую базу данных (если еще нет):
    ```bash
    sudo -u postgres createdb shelter_db
    ```

2.  Запустите скрипт из папки проекта, сохранив вывод в лог-файл для проверки результатов всех запросов:
    ```bash
    sudo -u postgres psql -d shelter_db -f shelter.sql > report.txt 2>&1
    ```
    *(Если вы работаете под другим пользователем СУБД, используйте флаги `-U username -W`)*.

3.  Просмотрите результат:
    ```bash
    cat report.txt
    # Или откройте report.txt в любом текстовом редакторе
    ```

### Способ 2: Интерактивный режим (psql)

1.  Зайдите в базу:
    ```bash
    sudo -u postgres psql -d shelter_db
    ```
2.  Внутри консоли выполните загрузку файла:
    ```sql
    \i shelter.sql
    ```
3.  Выход из клиента:
    ```sql
    \q
    ```

## Примеры полезных запросов

Все примеры находятся в секции "ЧАСТЬ 3: АНАЛИТИЧЕСКИЕ ЗАПРОСЫ" файла `shelter.sql`.

| № | Название | Описание | Используемые технологии |
|---|----------|----------|-------------------------|
| 1 | История болезней | Список всех медицинских процедур с именами пациентов | `INNER JOIN` |
| 2 | Дорогое лечение | Животные, чье совокупное лечение превысило 2000 руб. | `GROUP BY`, `HAVING`, `SUM` |
| 3 | Тревога по запасам | Товары на складе, требующие дозаказа (автоматически обновляется триггером) | `CASE WHEN`, `JOIN` |
| 4 | Текущее здоровье | Последний замер BCS и медицинский вердикт для каждого питомца | CTE, `ROW_NUMBER() OVER (...)` |
| 5 | Выздоровление | Атомарное оформление ремиссии дерматита у хомяка (статус + новая карта) | Транзакция (`BEGIN/COMMIT`) |
